# منصة الامتحانات على Cloudflare (خطة مجانية 100%)

> **القاعدة:** كل ما في هذا الدليل يعمل على Cloudflare Free — لا يطلب الدفع في أي خطوة، وإن ظهر طلب دفع فأنت في الصفحة الخطأ.

## المعمارية

```
الطالب (متصفح)
   │
   ▼  https://<اسم-الـWorker>.<حسابك>.workers.dev  (أو نطاق مخصص مجاني)
   الإنتاج الحالي: https://exams.mansa-eg.workers.dev (اسم الـWorker: exams)
Cloudflare Worker  (src/worker.js — منطق واحد يخدم الجميع)
   ├── ملفات ثابتة (public/) — واجهة الطالب + لوحة التحكم عبر CDN
   ├── /api/* — جلسات الامتحان والتصحيح (المفاتيح داخل حزمة الـWorker فقط، لا تُرسل للطالب أبدًا)
   ├── /<slug> — صفحة كل معلم (مثل /mostafa) بعلامته وألوانه
   ├── KV — المعلمون (+أرشيف) + حساب المسؤول (PBKDF2) + النتائج الأخيرة + منع التكرار
   ├── Durable Object (AttemptLimiter) — عدّادات ذرية: حدود المحاولات + سجل الطلاب المتمايزين لكل معلم (حد الطلاب)
   └── Google Apps Script (اختياري) — تمرير النتائج إلى جدول Google Sheets القائم
```

- **بنوك الأسئلة** (‎`src/data/banks.json`‎ — 1887 سؤالًا فريدًا / 127 امتحانًا، منها 80 معروضة و47 نموذجًا قديمًا محفوظًا) تُضمَّن في حزمة الـWorker (‏~359KB مضغوطة / 4.3MB غير مضغوطة — ضمن حدود كل الخطط؛ يُطبع الحجم عند `wrangler deploy --dry-run`).
- **المفاتيح لا تظهر** في أي استجابة قبل التسليم؛ التصحيح على الخادم فقط، والخلط بذرة عشوائية لكل جلسة (نفس خوارزمية تطبيق GAS الأصلي حرفيًا — مثبت بالاختبارات).
- **الطلاب لا يستخدمون رابط GAS إطلاقًا** — نقطة الدخول هي رابط Cloudflare.

## خطوات النشر (مرة واحدة، ~10 دقائق)

### 1) المتطلبات
- حساب Cloudflare مجاني + Node 18+ (على جهازك أو GitHub Codespaces).
- من مجلد `cloudflare/`:
```bash
npm install
npx wrangler login     # يفتح صفحة تفويض مجانية
```

### 2) ربط مساحة KV
النشر الإنتاجي لهذا المستودع يستخدم اسم الـWorker **exams** ومساحة KV المعرّفة
فعلًا في `wrangler.jsonc` (المعرّف `b2335d79-…` على حساب mansa-eg) — فلا شيء
تستبدله قبل النشر. عند إنشاء نشر جديد على حساب آخر:
```bash
npx wrangler kv namespace create PLATFORM_KV
```
ثم ضع الـ`id` الظاهر في `kv_namespaces[0].id` داخل `wrangler.jsonc`، وعدّل
`name` إلى اسم الـWorker المطلوب.

> ⚠️ درس من حادث إنتاج: عند تغيير `name` أو الـ`id` ينشر Wrangler Workerًا مختلفًا
> أو ربطًا يشير لمساحة فارغة — والكتابات اليدوية من Dashboard على المساحة الصحيحة
> لن يراها الـWorker. تحقق دائمًا من تطابق الاسم والمعرّض مع لوحة Cloudflare قبل
> النشر، وراجِع قسم «حدود الكتابة وأعطال 500» أدناه.

### 3) النشر
```bash
npm run build:banks   # (اختياري — مولد مسبقًا) يعيد توليد banks.json من ملفات .gs
npx wrangler deploy
```
الأسرار الموجودة على الـWorker (مثل `ADMIN_INITIAL_*`) لا يُمحوها النشر. لو كان
لديك ربط KV أُضيف يدويًا من Dashboard فقط، النشر من هذا الملف يطابقه (نفس المعرّف)
ولا يلغي أي بيانات.

ستحصل على رابط مثل: `https://exams.<حسابك>.workers.dev`
- صفحة المعلم الافتراضي: `…/mostafa`
- لوحة التحكم: `…/admin`

> الرابط يعمل بصيغة `<name>.workers.dev`. إن كنت تفضل لاحقة `pages.dev` تحديدًا فالمنصة متوافقة مع Cloudflare Pages أيضًا (نفس مجلد public + دالة داخل functions/)، لكن Workers هو المسار الموصى به رسميًا من Cloudflare ويدعم كل الميزات المستخدمة هنا.

### 4) حساب المسؤول (أول تشغيل)
افتح `…/admin`:
- إن لم يوجد حساب: تظهر شاشة **الإعداد الأولي** — أنشئ الحساب ببريدك الإلكتروني وكلمة المرور الابتدائية، ثم **غيّرها** من متصفحك لاحقًا بإعادة الإعداد… لا: كلمة المرور تُخزن PBKDF2-مُلَحًّا في KV ولا تُرسل لأي واجهة.
- أو زرع الحساب مسبقًا عبر أسرار (بدون شاشة إعداد):
```bash
npx wrangler secret put ADMIN_INITIAL_EMAIL
npx wrangler secret put ADMIN_INITIAL_PASSWORD
```
عند وجودهما يُنشأ الحساب تلقائيًا (idempotent) عند **أول أي طلب** على
`/api/admin/*` — بما في ذلك `GET /api/admin/status` الذي تستدعيه اللوحة تلقائيًا
عند فتحها، فلا حاجة لأي طلب خاص. خصائص الإقلاع:
  - لا يُعاد إنشاء حساب قائم ولا يُستبدل (قراءة تحقّق قبل الكتابة في كل جولة،
    وطلبات العزلة الواحدة المتزامنة تشترك في محاولة واحدة).
  - كتابات KV المرفوضة بـ429 (كتابة/ثانية/مفتاح أو الحصة اليومية) يُعاد
    محاولتها بتراجع أسي؛ والفشل النهائي يُسجَّل خادوميًا فقط ويُعاد بعد ٣٠ ثانية
    تلقائيًا على الطلب التالي — لا «فشل صامت دائم» يُبقي شاشة الإعداد للأبد.
  - إن استُنزفت الحصة اليومية تظهر رسالة عربية آمنة (503) بدل 500 غامض، وتُشفى
    تلقائيًا بعد إعادة ضبط الحصة منتصف الليل بتوقيت UTC.

**كلمة المرور الابتدائية لا تُكتب في أي ملف/كود/GitHub** — تُدخل مرة واحدة عبر الشاشة أو أمر `wrangler secret`.

### 5) (اختياري لكن موصى به) ربط النتائج بجدول Google Sheets القائم
1. في مشروع Apps Script الحالي (الذي يحوي `doPost` الجديد): من ⚙️ إعدادات المشروع → خصائص البرنامج النصي → أضف خاصية:
   - الاسم: `PLATFORM_RESULTS_SECRET` — القيمة: سر عشوائي طويل (مثلًا 32 حرفًا).
2. أعد نشر تطبيق الويب: Deploy → Manage deployments → ✎ → New deployment → Web app → Execute as: Me / Who has access: **Anyone**.
3. في Cloudflare:
```bash
npx wrangler secret put GAS_WEBAPP_URL        # رابط /exec الكامل
npx wrangler secret put GAS_RESULTS_SECRET    # نفس قيمة PLATFORM_RESULTS_SECRET
```
من هذه اللحظة تُضاف كل نتيجة إلى جدول النتائج نفسه (مع عمود جديد «المعلم») **وتُحفظ أيضًا في KV** كنسخة احتياطية. إن لم يُضبط الربط: تعمل المنصة كاملة وتُحفظ النتائج في KV فقط.

### 6) أسرار إضافية (اختياري)
```bash
npx wrangler secret put SESSION_SECRET   # توقيع الجلسات — وإلا يُولد تلقائيًا ويُخزن في KV
```

## إدارة المعلمين (من لوحة التحكم)
تبويب «المعلمون»: إضافة/تعديل معلم (الاسم، الهاتف الخاص، التخصص، واتساب/فيسبوك/تيك توك، صورة، نبذة، طلب رقم الهاتف، تفعيل/تعطيل)، توليد ID وslug ورابط عام تلقائيًا، نسخ الرابط، «لوحة المعلم» (نتائج/طلاب/متوسط/نجاح + حد الطلاب). كل المعلمين يشاركون نفس بنوك الأسئلة والامتحانات — الفرق هو الهوية والروابط وسياسات المعلم فقط. الصفحة العامة لكل معلم: `…/<slug>`.

- **حد الطلاب لكل معلم**: علم حقيقي «عدد طلاب غير محدود» (`studentLimitUnlimited`) أو حد رقمي `studentLimit` (0 = التسجيل مغلق للجدد، N = أقصى عدد طلاب متمايزين بالهاتف المُوحَّد). يُفرض على الخادم عند بدء الامتحان وعند التسليم داخل Durable Object واحد لكل معلم (ذري تحت التزامن — مُختبَر: حد 500/الحالي 499 + 6 تسجيلات متزامنة → 1 مقبول بالضبط). اللوحة تعرض الحد/الحالي/المتبقي. الطالب المسجَّل يواصل الدخول لكل الامتحانات حتى بعد امتلاء الحد.
- **حد المحاولات لكل امتحان** (اختياري): `unlimited` أو `maxAttempts` — ذري أيضًا.
- **دخول المعلم (رابط ثابت واحد)**: `…/teacher` — صفحة دخول فقط **بلا أي إنشاء حساب/تسجيل ذاتي**؛
  الحسابات تنشأ حصريًا من لوحة المسؤول (بريد أو اسم مستخدم + كلمة مرور PBKDF2 بملح فريد ومقارنة زمن-ثابت).
  كل معلم يحصل تلقائيًا على: `id` ثابت لا يتغيّر، `slug` فريد (مولَّد من الاسم إن تُرك فارغًا)، ورابط طلاب `…/<slug>` —
  الاسم قابل للتعديل دون كسر الرابط، والـslug لا يتغيّر إلا بطلب صريح (ورابط معلم مؤرشف لا يُمنح لغيره).
- **الحذف غير تدميري**: يُنقل المعلم إلى الأرشيف (قابل للاستعادة من نفس التبويب)، ولا تُحذف نتائجه ولا سجل طلابه؛ المعلم الافتراضي لا يُحذف بل يُعطَّل فقط.

### حدود الكتابة على KV وأعطال 500/503 (حادث موثَّق)
Cloudflare يفرض على كل الخطط: **كتابة واحدة في الثانية لكل مفتاح**، وعلى
الخطة المجانية **١٠٠٠ كتابة/يوم لكل الحساب**. تجاوز أي منهما يُرجع الخطأ
`KV PUT failed: 429 Too Many Requests`، بينما تبقى القراءات تعمل — فظهرت
الأعراض التالية: الدخول/الإعداد يُرجعان 500 بينما `/api/admin/status` يُرجع 200،
والكتابة اليدوية من Dashboard تنجح (لا تمر بحصة الـWorker).

المعالجة المضمَّنة في الكود:
- إعادة محاولة بتراجع أسي (٢٥٠/٦٠٠/١٢٠٠ms + جيتر) لكل قراءة/كتابة عابرة؛
  تُحلّ معظم أخطاء «كتابة/ثانية» تلقائيًا.
- `session_secret` يُكتب مرة واحدة لكل عزلة على الأكثر (كان يُعاد طلب كتابته
  مع كل طلب طوال فترة تأخر انتشار KV).
- بعد استنفاد المحاولات تُرجع مسارات المصادقة/الكتابة 503 برسالة عربية عامة
  آمنة — **بلا stack ولا اسم خطأ داخلي في الاستجابة** — والسبب الحقيقي في
  سجل الـWorker فقط.
- الواجهات العامة (الكتالوج/الإعدادات/الملفات العامة) تهبط للقيم الافتراضية
  وتستمر في العمل أثناء عطل التخزين.

متابعة حية:
```bash
npx wrangler tail exams --format pretty    # سجلات: [exammanasa:kv-put:admin] Error: KV PUT failed: 429 ...
Dashboard › Workers › exams › Logs         # observability مفعّل في wrangler.jsonc
```
إن رأيت 429 يوميًا: قلّل تسليمات الاختبار، أو فعّل تمرير النتائج إلى Google
Sheets (§5)، أو راجع عدد الكتابات (٤ لكل تسليم).

### إزالة مفاتيح التشخيص اليدوية بعد التحقق
بعد التحقق من الإقلاع والدخول على الإنتاج، تُحذف مفاتيح الاختبار المؤقتة:
```bash
npx wrangler kv key delete "TEST_ADMIN_KV" --namespace-id=b2335d799e2a4caabff6d9d4530f425c --remote
# مراجعة كل المفاتيح قبل الحذف:
npx wrangler kv key list --namespace-id=b2335d799e2a4caabff6d9d4530f425c --remote
```
(لا تحذف `admin` أو `session_secret` أو `sessv:*` أو `teachers` أو أي مفتاح `result:*`/`results:*`.)

## الأصول الثابتة وترويسات الأمان (`run_worker_first`)
`wrangler.jsonc` يضبط `assets.run_worker_first = true`. السبب: السلوك الافتراضي لـCloudflare
يخدم أي ملف موجود في `public/` **قبل** تشغيل الـWorker، فتُسلَّم `/` و`/admin` و`/teacher`
وكل ملف `.js`/`.css` بلا أي ترويسة أمان وبدون سياسة التخزين المؤقت التي يضبطها الـWorker.
بتشغيل الـWorker أولًا يمرّ كل طلب على `securityHeaders()` (nosniff، X-Frame-Options،
Referrer-Policy، Permissions-Policy وCSP)، وتُحوَّل `/index.html` و`/admin.html`
و`/teacher.html` تحويلًا دائمًا (308) إلى مساراتها القياسية حتى لا يُفهرس المحتوى مرتين.

## الأمان (مطبق ومُختبَر)
- التصحيح على الخادم حصرًا؛ لا مفاتيح في أي استجابة/HTML/JSON قبل التسليم (مُختبَر آليًا).
- جلسات امتحان موقعة HMAC-SHA256 بصلاحية 6 ساعات؛ رفض التلاعب والتسليم الناقص؛ منع إعادة التسليم (Cache + KV).
- لوحة التحكم: بريد/كلمة مرور (PBKDF2-SHA256، 120 ألف تكرار، ملح عشوائي)، كوكي HttpOnly+Secure+SameSite=Strict، حماية CSRF بثلاث طبقات (ترويسة `X-Requested-With` + تطابق `Origin` مع `Host` + `SameSite=Strict`) على كل مسار يغيّر الحالة **بما فيه `/api/admin/setup` و`/api/t/login`**، وتحديد معدل محاولات الدخول.
- أول تشغيل يُكتشَف عبر `GET /api/admin/status` (غير خاضع لتحديد المعدل) — لا عبر محاولة دخول فارغة، حتى لا يخفي قفل المحاولات شاشة الإعداد عن المالك.
- ترويسات أمنية على كل الاستجابات + تعقيم كل المخرجات (esc) + التحقق من روابط التواصل (http/https فقط).
- **إبطال خادومي للجلسات**: كل دخول يسجّل epoch في KV (`sessv:*`)؛ تغيير كلمة المرور أو إعادة تعيينها من المسؤول أو تعطيل/أرشفة المعلم تُسقط الجلسات الممنوحة فورًا (حتى لو كانت ضمن صلاحيتها)، مع إعادة إصدار كوكيز الجهاز الحالي عند التغيير الذاتي.
